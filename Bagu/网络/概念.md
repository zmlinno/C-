服务器 -  Server 提供服务的程序，通常运行在服务器上，等待客户端连接，处理请求

客户端 - Client 使用服务的程序，主要连接服务端，发送请求，用户通过它来操作



### TLS握手

1.浏览器发送 ClientHello，浏览器先告诉服务器，自己支持哪些TLS版本，加密算法，想访问的域名等信息，一个随机数，用于协商密钥的临时公钥材料

2.服务器回复 ServerHello
服务器选择双方都支持的参数，并发送自己的临时公钥材料，浏览器和服务器各用自己的临时私钥，以及对方发来的临时公钥，计算出相同的共享秘密，这个秘密不会直接通过网络发送，双方再根据它派生出后续加密所需的密钥

3.服务器出示证书并证明身份

服务器接着发送证书。浏览器会检查证书链是否可信、证书是否对应正在访问的域名、证书是否有效等。

服务器还会用与证书关联的私钥对握手内容进行签名，发送 `CertificateVerify`。浏览器用证书中的公钥验证签名，从而确认服务器确实持有对应的私钥。

注意：证书主要用于**验证服务器身份**，不是直接拿来加密所有网页数据的。

4.双方发送 `Finished`

服务器发送 `Finished`，客户端也会发送自己的 `Finished`。可以理解为双方检查：“我们看到的握手内容一致，协商出来的密钥也能正常工作。”

如果检查失败，握手会中断；成功后，双方就开始使用派生出的密钥保护后续数据。TLS 1.3 中，服务器的证书等后续握手内容已经受到握手密钥保护。

5.开始传输加密的 HTTP 数据

握手完成后，浏览器发送 HTTP 请求，服务器返回 HTTP 响应。TLS 通常用协商出的**对称密钥**加密和校验这些数据；对称加密适合高效地处理大量网页内容。
-证书和签名**：确认“我连到的是谁”；
-密钥协商**：让双方得到共同的会话密钥；
-对称加密**：保护之后传输的 HTTP 数据；
-Finished**：确认握手过程和密钥协商成功。



### 应用层协议
应用层协议规定数据的格式和通信规则，而具体数据可以HTML JSON 图片 文件或者设备控制命令。应用层协议通常建立在TCP和UDP上，例如HTTP和SSH通常使用TCP，而DNS查询通常使用UDP


## 详细的连接方式
用户在浏览器输入域名后，浏览器先通过DNS把域名解析为服务器对应的IP地址，得到IP地址之后，浏览器与TCP建立三次握手，建立可靠连接，接着进行TLS握手验证服务器证书，协商加密算法生成密钥，验证完成后，浏览器才发送经过TLS加密的HTTP请求，服务器解密并处理HTTP请求，然后返回经过TLS加密的HTTP响应，客户端收到IP接收数据包，由TCP来完成排序，重传并还原字节流，再由TLS解密，最后浏览器解析HTML，CSS和JavaScript并呈现网页
先TCP，后TLS，最后才是HTTP请求


## 关于三次握手
第一次客户端会发送SYN，并带上自己的初始序号，第二次服务器返回SYN-ACK，确认收到了客户端的请求，同时带上自己的初始序号，第三次客户端发送ACK，确认收到了服务器的序列。这样双方就确认了彼此的收发能力，是因为服务器发出SYN-ACK后，还需要确认客户端确实收到了这条响应

# 应用层
应用层为应用程序提供网络通信服务，并规定应用之间交换的数据和规则，例如HTTP用于网页通信，DNS用于域名解析，应用层产生或处理应用数据，传输层负责把数据送到目标主机上的对应的应用程序


# 表示层
表示层负责数据格式的处理和转换，让不同系统之间能够正确理解数据，比如说编码转换，加密解密以及压缩解压缩。


OSI7层模型
**OSI 七层模型是描述网络通信中不同功能如何分层的参考模型。从上到下分别是应用层、表示层、会话层、传输层、网络层、数据链路层和物理层。**  
应用层为应用程序提供网络服务，例如 HTTP、DNS；表示层处理数据的编码、格式转换、加密和压缩；会话层管理应用之间会话的建立、维持和结束；传输层负责端到端的数据传输，并通过端口号交给目标主机上的对应程序，TCP 还提供可靠、有序的传输；网络层使用 IP 地址进行寻址和路由，把数据包转发到目标主机；数据链路层把网络层的数据包封装成帧，通过 MAC 地址在相邻设备之间传输，并进行差错检测；物理层负责把比特转换为电、光或无线信号，在物理介质上传输。



## IP 地址和 MAC 地址有什么区别？数据包经过路由器时，哪些地址会变化？
客户端先查询本机缓存和 hosts 文件；没有结果时向递归 DNS 服务器发起查询。递归解析器先查缓存，缓存未命中时再从根 DNS、顶级域 DNS 查询到权威 DNS，获取对应的 A 或 AAAA 记录，然后把 IP 地址返回给客户端并缓存。


## 什么是端口， IP地址和端口分别用于标识什么？

ip地址用于标识网络中的目标主机，并帮助数据路由到该主机，端口号用于标识主机上的传输层通信端点，操作系统根据端口号连接信息，把数据交给对应的应用程序或服务。


## TCP为什么是三次握手，而不是四次
因为服务器可以把两个动作合并到同一个报文里：

- 确认客户端发来的 `SYN`；
- 同时发送自己的 `SYN`。

所以服务器用一个 **`SYN-ACK`** 就完成了这两件事，不需要拆成两次发送。

第三次握手中，客户端的 `ACK` 已经确认收到了服务器的 `SYN`。服务器收到这个 `ACK` 后，就知道客户端也收到了自己的序号，连接即可建立，因此通常不需要再发第四个确认报文。

可以记成：**三次刚好让双方都收到对方的序号并完成确认；服务器把“确认客户端”和“发送自己的 SYN”合并了。**


## TCP四次挥手
TCP 四次挥手用于释放连接。主动关闭方发送 `FIN`，被动关闭方回复 `ACK`；被动关闭方数据发送完毕后再发送 `FIN`，主动关闭方最后回复 `ACK`。由于 TCP 是全双工的，两个方向要分别关闭，因此通常是四次。


## TCP可靠传输
**TCP 的可靠传输，是指在连接正常的情况下，TCP 尽量保证数据无差错、按序、不重复地交付给接收端。**TCP 使用校验和检测数据是否损坏；用序列号标记数据顺序，接收端据此按序重组并丢弃重复数据；接收端通过 ACK 确认已收到的数据，如果数据或确认丢失，发送方会通过超时重传或快速重传恢复数据。  
此外，TCP 通过流量控制，根据接收窗口 `rwnd` 调节发送量，避免接收方缓冲区被塞满；通过拥塞控制，根据网络拥塞情况调节发送速率，避免网络过载。


## 序列号，确认号和ACK
TCP 用序列号标记字节流的位置，用确认号表示接收方下一步期望收到的字节序号；ACK 标志表示该确认号有效。接收方通过确认号告知发送方已收到哪些连续数据。



## TCP 的拥塞控制是什么？慢开始、拥塞避免、快重传、快恢复分别做什么？
TCP通过拥塞窗口cwnd控制网络中未确认的数据量。慢开始阶段让cwnd指数增长，达到慢开始阈值后进入拥塞避免阶段，改为线性增长。当发送方连续收到3个重复ACK时，会在超时之前执行快速重传；随后通过快速恢复将拥塞窗口降低到原来的一半左右，而不是直接降到最小。如果发生重传超时，则认为拥塞比较严重，将cwnd降到较小值并重新进入慢开始。


## 关于TCP为什么是面向字节流
TCP是面向字节流的协议，只保证字节可靠、有序地到达，不保留应用层每次send的消息边界。因此，多次send的数据可能被一次recv接收，形成粘包；一次send的数据也可能需要多次recv才能接收完整，形成拆包。粘包和拆包不是TCP错误，应用层需要通过固定长度、分隔符或者长度字段加消息体等方法恢复消息边界。





## HTTP 和 HTTPS 有什么区别？HTTPS 如何保证通信安全？
HTTP是一种应用层协议，传统HTTP/1.1和HTTP/2通常运行在TCP之上，数据本身不提供加密和身份认证。HTTPS本质上是HTTP over TLS，在HTTP和TCP之间增加了TLS安全层。TCP连接建立后，客户端和服务器先进行TLS握手，协商TLS版本和加密算法，客户端验证服务器证书，双方通过密钥交换生成会话密钥。之后使用对称加密保护HTTP请求和响应，并通过认证加密或完整性校验检测数据篡改。因此HTTPS主要提供服务器身份认证、通信机密性和数据完整性。





## HTTP 常见请求方法和状态码有哪些？
HTTP常见请求方法包括GET、POST、PUT、PATCH、DELETE、HEAD和OPTIONS。GET用于获取资源，POST用于提交数据或创建资源，PUT用于完整替换资源，PATCH用于局部更新，DELETE用于删除资源，HEAD只获取响应头，OPTIONS用于查询服务器支持的通信选项。  
HTTP状态码分为五类：1xx表示信息性响应，2xx表示成功，3xx表示重定向或缓存，4xx表示客户端错误，5xx表示服务器错误。常见状态码有200、201、204、301、302、304、400、401、403、404、405、429、500、502、503和504。
